# REST API сервера

Запуск: `npm run server` (порт 3001, переменные `PORT`, `DATA_DIR`; по умолчанию данные в `server/data/`).
Без внешних зависимостей (только Node.js 18+). Все ответы — JSON, кодировка UTF-8.
При `npm run dev` Vite проксирует `/api` на `http://localhost:3001`.

| Метод и путь | Что делает | Ответы |
|---|---|---|
| `GET /api/health` | проверка работоспособности | 200 `{status:"ok"}` |
| `POST /api/validate` | проверить спецификацию, ничего не сохраняя | 200 `{valid, errors[]}` |
| `POST /api/spec` | сохранить спецификацию | 201 `{id, url}`; 400 битый JSON; 413 больше 1 МБ; 422 `{error, errors[]}` |
| `GET /api/spec/:id` | получить `{id, createdAt, updatedAt, spec}` | 200; 404 |
| `PUT /api/spec/:id` | заменить спецификацию | 200; 404; 422 |
| `DELETE /api/spec/:id` | удалить | 204; 404 |
| `GET /api/specs` | список `[{id, title, owner, createdAt, updatedAt}]`, новые сверху | 200 |
| `GET /api/dictionary` | весь общий словарь `{ru:{…}, en:{…}}` | 200 |
| `PUT /api/dictionary/entries/:key` | задать переводы ключа: `{"ru":"…","en":"…"}`; пустая строка удаляет перевод этого языка | 200 (весь словарь); 400 |
| `DELETE /api/dictionary/entries/:key` | удалить ключ во всех языках | 200 (весь словарь) |
| `POST /api/dictionary/merge` | влить словарь `{ru:{…},en:{…}}` (входящее побеждает) | 200 (весь словарь) |

`id` — 12 символов `[a-f0-9]`; всё, что на него не похоже, получает 404 (защита от `../`).
Ключ словаря: латиница, цифры, `_`, не с цифры.

## Авторизация
Читать (`GET`) и проверять (`POST /api/validate`) можно без входа. **Изменять** формы и словарь — только вошедшим.
Сессия — случайный идентификатор в cookie `sid` (`HttpOnly`, `SameSite=Lax`, 7 дней; за HTTPS добавляйте `COOKIE_SECURE=1`).

| Метод и путь | Что делает | Ответы |
|---|---|---|
| `POST /api/auth/register` `{username,password,role?}` | **Пока в системе нет ни одного пользователя** — любой создаёт первого: он становится `admin` и сразу входит. **Дальше — только администратор** создаёт пользователей (роль `editor` по умолчанию или `admin`); сессия администратора не меняется | 201 `{user}`; 400 (логин 3–32 символа `A-Za-z0-9_.-`, пароль 8–200, неизвестная роль); 401/403 не админ; 409 логин занят |
| `POST /api/auth/login` | войти | 200 `{user}`; 401 (одинаково для неверного пароля и неизвестного логина); 429 после 5 неудач за минуту |
| `POST /api/auth/logout` | выйти (сессия удаляется на сервере) | 204 |
| `GET /api/auth/me` | кто я: `{user\|null, requireAuth, registrationOpen}` (`registrationOpen` — true, пока нет ни одного пользователя) | 200 |
| `DELETE /api/users/:id` | удалить пользователя, только `admin`: его сессии гаснут сразу, логин освобождается, его формы остаются без владельца (правит только админ). Себя удалить нельзя | 204; 400 (себя); 401/403; 404 |
| `GET /api/users` | список пользователей (без паролей), только `admin` | 200; 401; 403 |

Права: изменять или удалять форму может её владелец или `admin` (иначе 403); словарь меняет любой вошедший.
Без входа изменяющие запросы дают 401.

Настройки сервера (переменные окружения): `COOKIE_SECURE=1` — за HTTPS; `AUTH=off` — отключить авторизацию (только для локальной разработки).

Как хранится: пароли — scrypt с индивидуальной солью; в файле сессий лежит только SHA-256 идентификатора;
`users.json` и `sessions.json` создаются с правами `0600`.

## Примеры (curl)

```
curl http://localhost:3001/api/health

curl -X POST http://localhost:3001/api/validate \
  -H 'Content-Type: application/json' \
  -d '{"title":"T","elements":[{"name":"a","label":"A","type":"text"}]}'

curl -X POST http://localhost:3001/api/spec -H 'Content-Type: application/json' -d @example-spec.json
curl http://localhost:3001/api/spec/<id>

curl -c cookies.txt -X POST http://localhost:3001/api/auth/login \
  -H 'Content-Type: application/json' -d '{"username":"alice","password":"password1"}'

curl -b cookies.txt -X PUT http://localhost:3001/api/dictionary/entries/save_btn \
  -H 'Content-Type: application/json' -d '{"ru":"Сохранить","en":"Save"}'
curl http://localhost:3001/api/dictionary
```

## Как устроено
- Валидация — тот же `src/core/validateSpec.js`, что и в браузере: правила не дублируются.
- Файлы пишутся атомарно (временный файл → `rename`), записи словаря идут через очередь —
  одновременные правки не теряются (проверено тестом на 30 параллельных запросов).
- Клиент словаря шлёт **операции над отдельными ключами**, а не весь словарь, и накладывает
  ответ сервера поверх своих неотправленных правок — чужие изменения не затираются.

## Ограничения (осознанные)
- Права пока простые: две роли, владелец формы. Нет смены/сброса пароля, подтверждения почты, управления пользователями (все эти шаги — следующие).
- Ограничение попыток входа хранится в памяти и сбрасывается при перезапуске сервера.
- Сессия действует 7 дней с момента входа (без продления).
- Если два человека одновременно правят **один и тот же** ключ — побеждает последняя запись.
- Хранилище — файлы; для сотен тысяч записей понадобится БД.
